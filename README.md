# NAND 闪存仿真器 + 页映射 FTL（植保无人机飞行日志场景）

针对"飞控日志写入裸闪存、掉电丢日志、闪存寿命远低于标称"这个问题，实现一个
从 NAND 设备模型到 FTL、再到掉电验证与磨损报告的完整仿真链路。

```
flashsim/
  config.py       几何参数与 FTL 配置（预留空间比例、GC 策略、坏块率…）
  device.py       裸 NAND die：严格的页/块规则 + 确定性掉电注入
  ftl.py          页级映射、保留区快照、GC 双策略、动态/静态磨损均衡、
                  坏块表、丢弃通知、多平面编程
  workload.py     按飞行日志写入规律生成的确定性操作流
  powerloss.py    掉电测试台（影子副本 + 恢复校验）
  experiment.py   正式实验：数百万次写 + 随机掉电 + 两策略对比
  report.py       自包含 HTML 报告编排
  report_assets.py 报告用 SVG 图元（块地图 / 柱状图 / 折线图，无外部依赖）
tests/            32 个测试：设备规则、FTL 行为、掉电一致性
runs/             实验结果 JSON
report/index.html 可视化报告
```

## 运行

```bash
python3 -m pytest tests/ -q                                  # 全部测试
python3 -m flashsim.experiment                               # 完整实验（约数分钟）
python3 -m flashsim.experiment --quick                       # 快速冒烟版
```

实验是确定性的：同样的参数得到同样的数字。

## 八项需求的落点

| # | 需求 | 实现 |
|---|------|------|
| 1 | 整块擦除、页只能按顺序写一次，违规报错 | `device.py`：`FlashError` 覆盖重复编程、乱序编程、非整块擦除、坏块访问；空洞允许跳过但不允许回填 |
| 2 | 页映射在内存 + 保留区另存 | `ftl.py`：`map[]` 常驻内存；元数据区按 **多 Bank 轮转** 写全量快照，含每页 CRC 与提交页；重启优先加载最新有效快照，否则全盘扫描标签重建 |
| 3 | 回收综合有效页数与擦除次数，另做只看有效页数的对照 | `gc_policy="cost"` 用 cost-benefit 比值 `死页比例 / (1 + 权重 × 相对擦除次数)`；`gc_policy="greedy"` 只看有效页数。零有效页的块一律免搬运优先回收 |
| 4 | 动态 + 静态磨损均衡，冷数据会被搬走 | 动态：空闲块按擦除次数排序分配；静态：擦除极差超阈值时搬迁"闲置且擦除次数低"的块（`test_static_wl_moves_cold_pages` 验证 0 → 全搬） |
| 5 | 坏块表，出厂坏块与使用中坏块都绕开 | 出厂坏块在初始化时排除；擦除失败即刻标记并写入 **双块镜像的坏块日志**（掉电后仍能恢复）；退役次数超 P/E 的块不再分配 |
| 6 | 多平面并行写 | `write_pair()`：两个逻辑页落到同一超块对、同一页偏移，一次 NAND 操作（测试断言设备操作数 == 1） |
| 7 | 丢弃通知，回收时不搬 | 丢弃记录先落盘再撤映射；GC 只搬 `map[lpn] == ppn` 的页，被丢弃的页直接跳过 |
| 8 | 预留空间可配，统计写放大与剩余寿命 | `op_ratio` 可配；`wa()` 按物理编程页 / 主机页统计；寿命以 **最热块** 为准外推 |

## 实验结果

完整实验（399 万次主机写，2 个平面 × 1024 块/平面 × 256 页 × 4 KiB）：

| 指标 | 只看有效页数 | 有效页数 + 擦除次数 |
|------|-------------|--------------------|
| 写放大 | 1.671 | 1.672 |
| 块擦除次数 | 27,551 | 27,564 |
| 擦除次数极差 / σ | 5 / 1.02 | 3 / 0.67 |
| 最热块已用寿命（P/E 3,000 加速实验） | 0.53% | 0.50% |
| 运行期新增坏块 | 2 | 0 |

在 10% 预留空间下两者几乎持平——因为回收到的块基本都是纯垃圾，策略选谁不难。
把预留空间收紧后才拉开差距（见 `report/index.html` 的"预留空间扫描"）：

| 预留空间 | greedy WA | cost WA | WA 改善 | 极差 greedy→cost |
|---------|-----------|---------|---------|------------------|
| 20% | 1.923 | 1.906 | -0.9% | 8 → 5 |
| 12% | 2.527 | 2.388 | -5.5% | 9 → 7 |
| 8%  | 2.993 | 2.935 | -1.9% | 11 → 10 |
| 5%  | 5.208 | 4.656 | -10.6% | 21 → 17 |

掉电：两种策略各 40 次随机切电，全部通过。greedy 的切点中有 30 次撕裂
（多平面只落一页或页标签 CRC 损坏）、10 次整体中止；cost 为 25 / 15。
另做过一轮 200 次的独立压力扫描（不在默认报告内），同样 0 失败。

重启后每个逻辑页读到的都是掉电前最后一次已确认写入的内容；掉电瞬间在途的那一页
允许旧值 / 新值 / 未映射三态，出现其它任何内容即判失败。快照尚未写完时切电会回退
到更旧的一份快照或全盘扫描（40 次里有 2–3 次走这条路径），结果同样正确。

## 掉电正确性的论证

* 每个数据页的备用区带 `(lpn, seq)` 与 CRC；
* 主机写在**成功返回时**已落入闪存（单页或双平面成对），影子副本就在此刻更新；
* GC **先搬后擦**，搬出的副本拿到更大的 `seq`，掉电在两者之间时原件仍然有效；
* 丢弃记录先写保留区再撤内存映射，重启不会从陈旧数据页复活；
* 快照写往"当前未持有最新快照"的那个 Bank，轮转期间最新快照始终可读；
* 重启把 `seq` 恢复到全盘最高值之上，保证新写一定覆盖旧版本。

掉电测试台在 NAND 操作边界切电，且该次操作可能是：整体丢弃 / 多平面只落一页 /
页标签损坏。恢复后逐页比对：

* 已确认的写 → 必须读到该内容；
* 已确认的丢弃 → 必须读不到；
* 掉电瞬间在途的操作 → 允许旧值、新值或未映射，出现其它任何内容即判失败。

`tests/test_powerloss.py` 覆盖随机点、GC 搬运途中、检查点轮转途中三类切电位置。

## 已知边界

* 预留空间低于约 5% 且叠加坏块时，设备会真的写满；FTL 抛 `NoSpace`，实验按
  "设备已满"终止并照常做恢复校验。这是容量约束，不是一致性缺陷。
* 快照是全量写，元数据区按快照大小自动划分 Bank（至少 2 个），`Config` 会在
  块数不足时直接报错并给出所需块数。
* 元数据区内的出厂/运行期坏块会被跳过；Bank 写满时先写快照（把丢弃记录折叠进
  映射表）再回收旧 Bank，绝不丢失仍生效的丢弃记录。
* 不建模读干扰 / 随机位翻转，焦点是掉电与磨损。
